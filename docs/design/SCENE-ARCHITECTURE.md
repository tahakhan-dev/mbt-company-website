# SCENE ARCHITECTURE — engine runtime design

Status: DRAFT for Creative Gate A (technical shape; implementation begins Phase 2/3).
Stack locked: Astro SSR + Netlify adapter, Three.js **r158**, WebGL2-first, custom GLSL,
`postprocessing` (SMAA + ACES-equivalent grade only), custom rAF timeline. No GSAP, no Spline,
no copied engine code.

## 1. Runtime topology

One persistent `<canvas>` owned by the public layout (`src/layouts/PublicLayout.astro`), fixed,
behind DOM. One `EngineRuntime` singleton (vanilla TS, zero React) with:

- `capabilities`: WebGL2/1/none, `prefers-reduced-motion`, `deviceMemory`, DPR, coarse pointer,
  `saveData` → resolves **Tier A/B/C** once per session (re-evaluated on context loss).
- `masterState`: `{ route, sceneProgress (0..1 per chapter), pointer (damped), viewport, theme,
  visibility }` — the ONLY input scenes read. Scroll → normalized progress happens in one place;
  measurements refresh after fonts/critical media load.
- `timeline`: named tracks (`camera`, `lights`, `moduleN`, `uniforms.*`) with keyframes +
  brand easings from MOTION-MATRIX. Pure functions of progress — scrubbing is free, and Tier C
  posters are just sampled keyframes.
- `sceneRegistry`: per-route scene modules, lazy `import()`ed on route intent (hover/viewport
  prefetch when reasonable). Each scene: `init(ctx) / update(state) / resize / dispose`.
  `dispose` is audited: geometries, textures, render targets, listeners — counted in dev, asserted
  zero-leak in tests.
- Lifecycle: pause on `document.hidden`, on canvas fully off-screen, and after 5s pointer+scroll
  idle (resume on input). `webglcontextlost/restored` handled: restore once, else drop to Tier C
  permanently (no reload loops).

Astro route transitions: View Transitions API for DOM; the runtime survives navigation (persisted
island/root script), receives `route` change, runs the ≤700ms handoff track. Deep links and
back/forward always render the destination immediately; the handoff is decorative on top.

## 2. First-paint contract

HTML/CSS hero paints complete with zero JS. Engine bundle is a separate deferred chunk loaded
after LCP (`requestIdleCallback` + first-interaction race). Canvas fades in beneath already-
readable content. Initial route JS (excl. engine, excl. admin) budget: <170KB gzip.

## 3. The Engine asset

- Authored procedurally in code (original): 12 module bodies from a shared parametric kit
  (ceramic shell + titanium chassis + glass face + conduit sockets), instanced where possible,
  engraved markings via SDF texture atlas (generated by our own script, committed as source).
  Target: whole engine ≤120k triangles Tier A / ≤45k Tier B, ≤40 draw calls via merged/instanced
  batches.
- Materials: custom PBR-lite GLSL (we own the shaders): ceramic (soft sheen), titanium
  (anisotropic brush), glass (single-pass refraction via scene color copy — no real transmission),
  conduit emission (uniform-driven per module).
- Lighting: 1 key + 1 fill directional, 1 environment (small prefiltered env map, our own render),
  per-module emissive. Color management: `SRGBColorSpace` + ACES filmic tone mapping (r158 API).
- Postprocessing: SMAA + subtle grade. No bloom crutch; emission handled in-shader.
- Compression: geometry generated at runtime from params (tiny JS, no GLB download) — if any
  authored mesh is needed later, Draco/Meshopt GLB + KTX2 textures.

## 5. Tier C (designed static mode)

Build step renders authored stills per chapter from the same scene code (headless GL or
Playwright capture at build time) → optimized AVIF/WebP posters served as `<picture>`. CSS-only
reveals. This is also the no-JS, print, and crawler experience — content and conversion identical.

## 6. Console-zero and diagnostics

Production: no warnings, no errors, no Three.js deprecation notices. Dev-only overlay: FPS, draw
calls, memory, tier, progress readouts (also feeds the frame's mono annotations — diagnostics as
brand).

## 7. Test hooks

Runtime exposes `window.__aigenvora` (dev/test builds only): current tier, scene, progress,
disposal counters — Playwright asserts scene swaps, disposal-on-exit, pause-on-hidden, context-loss
recovery, and captures the visual-regression keyframes listed in MOTION-MATRIX.
